# ServerAgentLink 使用说明

ServerAgentLink 是一个轻量的「服务器 + 编码账户」管理系统，用于打通「部署在服务器上的 Claude Code」与「云桌面宿主机上的个人助理 agent（coclaw/hermes）」：

- **给管理员用**：一个可视化 Web 平台，添加服务器、在服务器上真实创建/删除 OS 用户、给用户分配逐目录读写权限、标记账户是否具备编码能力、配置是否把账户暴露给 agent。
- **给 agent 用**：一个只读的 MCP 服务，按配置暴露被标记账户的 SSH 凭据与目录权限清单，agent 拿到后自行 SSH 到服务器、在授权目录内驱动 Claude Code。

平台是**凭据目录 + 服务器管理员**，**不是**任务代理，也**不管理** Anthropic API Key——Claude Code 需在服务器上手工安装并配置。

---

## 1. 构建与部署

```bash
# 一键运行（自动生成 .env → 构建 → 启动）
./run.sh

# 或手动：复制配置模板并编辑
cp .env.example .env

# 构建单二进制
go build -o server-agent-link ./cmd/server-agent-link

# 运行（自动读取 .env；真实环境变量优先）
./server-agent-link
```

产物是单个静态二进制，无需数据库服务、无需 Node 构建链，可交叉编译后拷贝到任意 Linux 主机运行。配置项见 [.env.example](../.env.example)，也可用环境变量覆盖（见 §2）。

### 前置条件（目标服务器）

权限管理采用 **ACL 后端**（唯一支持的后端），目标服务器需满足：

1. 安装 `acl` 包：Debian/Ubuntu 用 `apt-get install acl`，RHEL/CentOS 用 `yum install acl`。
2. 被授权目录所在文件系统需以 `acl` 选项挂载（`mount -o remount,acl /`，或在 `/etc/fstab` 加 `acl`）。

否则 `setfacl` 会失败，对应账户状态会被标记为 `error`。

## 2. 环境变量

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `SAL_LISTEN_ADDR` | 否 | `:8080` | 监听地址 |
| `SAL_DATA_DIR` | 否 | `./data` | 数据目录（SQLite + `master.key` + `admin-password.txt`） |
| `SAL_MASTER_KEY` | 否 | 自动生成 | 32 字节 hex 主密钥；用于加密库中的 root/账户密码。**一旦写入数据必须保持不变**（见 §7） |
| `SAL_MCP_TOKEN` | **是** | — | MCP 端点的静态 Bearer token（agent 接入用） |
| `SAL_ADMIN_USER` | 否 | `admin` | 管理员用户名 |
| `SAL_ADMIN_PASSWORD` | 否 | 自动生成 | 首次运行的管理员密码；缺省时生成随机密码写入 `$SAL_DATA_DIR/admin-password.txt`（0600） |
| `SAL_TLS_CERT` | 否 | — | TLS 证书路径（与 `SAL_TLS_KEY` 成对设置） |
| `SAL_TLS_KEY` | 否 | — | TLS 私钥路径（与 `SAL_TLS_CERT` 成对设置） |

> `SAL_TLS_CERT` 与 `SAL_TLS_KEY` 必须同时设置或同时不设。设置了则监听 HTTPS 且会话 cookie 带 `Secure` 标记；未设置则监听明文 HTTP（生产环境建议反向代理或直接启用 TLS，因为管理员登录与 root 密码都经此通道传输）。

## 3. 首次运行

1. 若未设 `SAL_ADMIN_PASSWORD`，启动后随机管理员密码写入 `$SAL_DATA_DIR/admin-password.txt`（权限 0600），**不会打印到日志/stdout**。
2. 若未设 `SAL_MASTER_KEY`，启动时在 `$SAL_DATA_DIR/master.key` 生成 32 字节随机主密钥。
3. 浏览器打开 `http://<host>:8080/login`，用管理员用户名/密码登录。

## 4. Web UI 使用流程

1. **登录**：在 `/login` 输入管理员用户名与密码。
2. **添加服务器**：首页「添加服务器」表单填写名称、主机 IP/域名、SSH 端口（默认 22）、root 用户名（默认 root）、root 密码。**「root 用户」不要求是真正的 root（uid 0）**——只要该账户能免密 `sudo`（sudoers 含 `NOPASSWD`），平台建户/删户/改权限时会自动 `sudo -n` 提权；真 root 则直接执行，不依赖 sudo 是否安装。
3. **测试连通**：服务器列表或详情页的「测试连通」按钮会做一次真实 SSH 拨号，验证主机可达、root 密码正确、主机指纹匹配，成功后固定指纹并在「状态」列显示「已验证」。若目标主机迁移/重装导致指纹变化，测试会报 `host key mismatch`，需先「重置指纹」（见 §7）。
4. **新建账户**：进入某服务器详情页，「新建账户」表单填写用户名、密码，勾选「编码能力」「暴露给 agent」，并在「目录权限」栏填入 `路径=模式`（逗号分隔，如 `/data/a=rw,/data/b=ro`）。提交后平台会 SSH 到服务器真实执行 `useradd` + `chpasswd` + `setfacl`。若用户名在服务器上已存在，则重置其密码并应用权限（幂等，等价于「接管已有账户」）。
5. **查看账户与目录**：详情页以表格列出该服务器的全部账户，并直接显示每个账户的目录权限清单（`路径=模式`）与状态（正常/异常/待建户）；账户异常时内联显示失败原因（如权限不足、目录不存在）。
6. **切换「编码/暴露」**：账户行的「编码」「暴露」为可点击开关，点一下即切换该账户的编码能力 / 是否暴露给 agent，即时保存（后端 `PUT /api/accounts/{id}`）。
7. **首页暴露概览**：首页「已暴露给 agent 的账户」区块跨服务器汇总列出 agent 实际能拿到的账户（服务器/主机/账户/编码/目录权限，**不含密码**）。
8. **改权限**：账户行「改权限」编辑 `路径=模式` 列表并保存，会真实推送 ACL（含撤销被移除目录）。
9. **改密码**：账户行「改密码」重置该 OS 用户密码并同步更新库中加密凭据。
10. **重新建户**：账户行「重新建户」对已存在的 OS 用户重跑密码设置与 ACL 授权（幂等），用于修复 `error` 状态。
11. **删除账户**：先 SSH 到服务器 `userdel -r` 删 OS 用户，成功后才删库；远端失败则保留记录并标记 `error`，供重试。

## 5. REST API 参考

所有 `/api/*`（除 `/api/login`、`/api/logout`）都需登录（`sal_session` cookie）。**状态变更方法**（POST/PUT/DELETE）额外要求 CSRF：请求须带 `sal_csrf` cookie，并以 `X-CSRF-Token` 头回传相同值。浏览器内由前端自动处理；脚本调用时需自行维护。

### 鉴权

| 方法/路径 | 说明 |
|---|---|
| `POST /api/login` | `{"username","password"}` → 设置 session + csrf cookie |
| `POST /api/logout` | 清除 session + csrf cookie |

### 服务器

| 方法/路径 | 请求体 | 说明 |
|---|---|---|
| `GET /api/servers` | — | 列表（不含 root 密码） |
| `POST /api/servers` | `{"name","host","ssh_port","root_user","root_password"}` | 添加 |
| `GET /api/servers/{id}` | — | 详情 |
| `POST /api/servers/{id}/test` | — | 连通性测试，返回 `{"connected":bool,"host_key"/"error"}`；成功即固定指纹并记录验证时间 |
| `PUT /api/servers/{id}` | 任意子集；含 `reset_host_key:true` 或更换 `host` 会清空已固定的 SSH 指纹 | 更新 |
| `DELETE /api/servers/{id}` | — | 删除（先逐个远程删 OS 用户，全部成功才删库） |

### 账户

| 方法/路径 | 请求体 | 说明 |
|---|---|---|
| `GET /api/servers/{id}/accounts` | — | 列出该服务器账户（含逐目录权限） |
| `POST /api/servers/{id}/accounts` | `{"username","password","coding_capable","exposed_to_agent","permissions":[{"path","mode"}]}` | 建户并真实 provision |
| `POST /api/accounts/{id}/provision` | — | 重新建户（幂等） |
| `PUT /api/accounts/{id}` | `{"coding_capable"?, "exposed_to_agent"?}` | 翻转标志 |
| `PUT /api/accounts/{id}/password` | `{"password"}` | 重置该 OS 用户密码并更新库中加密凭据 |
| `DELETE /api/accounts/{id}` | — | 删户（先远程删 OS 用户） |
| `GET /api/accounts/{id}/permissions` | — | 列出权限 |
| `PUT /api/accounts/{id}/permissions` | `[{"path","mode"}]` | 覆盖权限（含撤销被移除目录的 ACL） |

- `mode` 取值：`rw`（读写）| `ro`（只读）。
- 账户 `status` 取值：`pending` | `active` | `error`。

## 6. MCP 接入（agent 侧）

MCP 服务是 **streamable HTTP**，地址 `/mcp`，用静态 Bearer token 鉴权，暴露一个只读工具 `list_exposed_accounts`。

```bash
curl -H "Authorization: Bearer <SAL_MCP_TOKEN>" \
     -H "Content-Type: application/json" \
     -H "Accept: application/json, text/event-stream" \
     -X POST \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"list_exposed_accounts","arguments":{}}}' \
     http://localhost:8080/mcp
```

返回示例（只含 `exposed_to_agent=1` 且服务器 `enabled=1` 的账户）：

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [{
      "type": "text",
      "text": "{\"accounts\":[{\"server_id\":\"...\",\"server_name\":\"dev1\",\"host\":\"10.0.0.5\",\"ssh_port\":22,\"username\":\"coder1\",\"password\":\"...\",\"coding_capable\":true,\"directories\":[{\"path\":\"/data/repo\",\"mode\":\"rw\"}]}]}"
    }]
  }
}
```

agent 拿到账户后，在授权目录内用 SSH 驱动 Claude Code：

```bash
sshpass -p '<password>' ssh -o StrictHostKeyChecking=accept-new \
  coder1@10.0.0.5 -p 22 \
  'cd /data/repo && claude -p "实现 <任务>" --dangerously-skip-permissions'
```

> MCP 端点会返回**明文凭据**，务必用强 `SAL_MCP_TOKEN` 保护，并仅在内网/受信环境暴露。

## 7. 安全与运维要点

### 主密钥（务必谨慎）

- 库中所有 root/账户密码用 **AES-256-GCM** 加密，密钥来自 `SAL_MASTER_KEY` 或 `$SAL_DATA_DIR/master.key`。
- **切换密钥来源 / 丢失密钥 = 永久失去所有已存密码的访问权。** 为防误操作，程序做了保护：
  - 设置了 `SAL_MASTER_KEY` 但格式非法 → 启动报错，不回退。
  - `master.key` 存在但长度不是 32 字节 → 启动报错，不覆盖。
  - `master.key` 不存在但数据库已存在（说明曾用 env 密钥运行）→ 启动报错，要求显式提供原密钥。
- 生产环境建议用密钥管理工具保存主密钥，并用 `SAL_MASTER_KEY` 显式注入。

### SSH 主机指纹（TOFU）

- 首次成功连接会记录目标 SSH 主机的 SHA256 指纹，之后每次连接校验，指纹不符即拒绝（防中间人）。
- 若目标主机**迁移 / 重装系统导致指纹变化**，两种方式复位：
  1. `PUT /api/servers/{id}` 携带 `"reset_host_key": true`；
  2. 直接在 `PUT` 中更改 `host` 字段（自动清空指纹）。

### SSH 提权（sudo）

- 平台以「root 用户」身份 SSH 登录后执行 `useradd` / `chpasswd` / `setfacl` / `userdel`。
- 若该账户是普通用户（uid != 0），脚本自动改用 `sudo -n` 提权；要求 sudoers 为该账户配置 `NOPASSWD: ALL`，否则 `sudo -n` 立即报错（账户标记 `error`，原因内联显示在详情页）。
- 若使用真正的 root（uid 0），则不调用 sudo，目标机无需安装 sudo。

### 登录与 CSRF

- 管理员密码用 argon2id 哈希，绝不落明文。
- 会话用 HMAC-SHA256 签名 cookie（`HttpOnly`、`SameSite=Strict`、启用 TLS 时加 `Secure`）。
- 登录限流 5 次/分钟/IP（按 `RemoteAddr`，不信任 `X-Forwarded-For`）。
- 状态变更接口启用 double-submit CSRF 防护。

### 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 账户状态 `error` | 目标不可达 / root 密码错 / 目录不存在 / 无 ACL | 修正后点「重新建户」或调用 provision |
| 账户状态 `error`（权限不足） | SSH 登录账户非 root 且无免密 sudo | 给该账户配置 `NOPASSWD: ALL`，或改用真 root 账户 |
| `host key mismatch` | 目标指纹已变化 | 用 `reset_host_key` 或改 `host` 复位指纹 |
| `SAL_MCP_TOKEN must be set` | 未设置 MCP token | 设置环境变量后重启 |
| 解密失败（`message authentication failed`） | 主密钥变了 | 恢复原 `SAL_MASTER_KEY` / `master.key` |

## 9. 安全边界说明（明确不做/需自行承担）

- **不做任务代理**：平台只暴露凭据目录，agent 自行 SSH 并驱动 Claude Code。
- **不管理 Anthropic API Key**：Claude Code 的安装、URL/token 配置由人工在服务器上完成。
- **单管理员模式**：无多用户、无分级权限。
- **明文 HTTP**：未启用 TLS 时，登录与 root 密码走明文通道；生产环境务必启用 `SAL_TLS_CERT`/`SAL_TLS_KEY` 或前置 HTTPS 反向代理。
