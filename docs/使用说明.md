# ServerAgentLink 使用说明

> 面向管理员的完整操作手册。快速上手看 [README](../README_ZH.md)，本篇覆盖部署、全部功能、API、MCP 接入、安全运维与故障排查。

ServerAgentLink 把**多台服务器的目录安全地暴露给本地 agent**：管理员在平台上登记服务器、创建（或 attach）真实 OS 账户、按目录授予只读/读写 ACL，被暴露的账户凭据经 MCP 提供给本地助理 agent（任意支持 MCP 的助理 agent），agent 随后在**且仅在**授权目录内工作——编码、查日志、改配置皆可，越界访问在 OS 层被拒绝。

**授权即边界**：agent 拿到的是一批最小权限 OS 账户，不是 root；真实访问控制由服务器上的 POSIX ACL 执行，平台只负责供给与回收。平台本身**不是**任务代理，也**不管理** Anthropic API Key——以驱动 Claude Code 为例，agent 在授权目录里执行 `claude -p "任务"` 只是众多用法之一，平台不关心也不限制目录内跑什么。

## 1. 概念与架构

### 1.1 核心概念

| 概念 | 说明 |
|---|---|
| **服务器（Server）** | 一台可通过 SSH 管理的目标主机。登记时提供主机地址、SSH 端口、管理账户（用户名+密码）。 |
| **管理账户** | 登记服务器时填的账户，用于在服务器上执行供给操作。按能力分三级：`root` / `sudo` / `plain`（见 §6）。 |
| **账户（Account）** | 服务器上的真实 OS 用户。可以由平台创建（root/sudo 模式），也可以是已有账户接入（plain 模式 attach）。 |
| **目录权限（Permission）** | 某账户对某目录的 `rw`（读写）或 `ro`（只读）授权，用 POSIX ACL 落地，含默认 ACL（目录内新建文件自动继承）。 |
| **暴露（Expose）** | 账户级开关。打开后该账户的 SSH 凭据与目录清单才会出现在 MCP 目录里。 |
| **到期（Expiry）** | 账户级 RFC3339 时刻。到期后凭据立即从 MCP 消失，远端账户随后被锁定（或 plain 模式撤 ACL）。 |
| **MCP 目录** | 一个只读 MCP 工具 `list_exposed_accounts`，返回全部「已暴露、未到期、服务器启用」的账户凭据。 |

### 1.2 架构

```
┌─────────────┐        ┌──────────────────────────────────────────┐
│   浏览器      │  HTTP  │  ServerAgentLink（单 Go 二进制）          │
│  (Web UI)    ├───────►│                                          │
└─────────────┘        │  Web UI（内嵌模板） ──► REST API          │
                       │        │                  │               │
┌─────────────┐        │        ▼                  ▼               │
│  本地 agent   │  MCP   │  MCP 服务(streamable HTTP, Bearer)       │
│ (任意       ├───────►│   list_exposed_accounts（只读）           │
│  MCP agent)  │        │        │                                  │
└─────────────┘        │        ▼                                  │
                       │  SSH 执行器（useradd/chpasswd/setfacl/    │
                       │  userdel/usermod，按 access_mode 分流）    │
                       │        │                                  │
                       │  SQLite 存储（AES-256-GCM 加密凭据，       │
                       │  user_version 版本化迁移）                 │
                       │        │                                  │
                       │  到期回收器（10 分钟扫描）                  │
                       └───────────────┬──────────────────────────┘
                                       │ SSH
                       ┌───────────────┴──────────────┐
                       │  服务器 A        服务器 B …    │
                       │  (OS 账户 + 逐目录 ACL)        │
                       └──────────────────────────────┘
```

### 1.3 安全模型（四层边界）

1. **OS 账户隔离**：每个被暴露账户是独立 OS 用户，不与 root 或他人共享凭据；进程级隔离（home、umask、shell）天然存在。
2. **逐目录 ACL**：`setfacl` 精确到目录的 `rw`/`ro`（含默认 ACL 继承）；白名单之外按服务器原有权限语义拒绝。
3. **平台侧开关**：`exposed_to_agent` 决定凭据是否进 MCP 目录；`expires_at` 决定暴露何时自动终止。
4. **平台自身安全**：凭据 AES-256-GCM 加密落库、MCP 静态 Bearer、argon2id 管理员 + HMAC 会话 + CSRF + 登录限流、SSH TOFU 指纹、操作审计日志。

## 2. 安装与部署

### 2.1 一键运行（推荐）

```bash
./run.sh
```

脚本自动完成：生成 `.env`（若缺省，并为 `SAL_MCP_TOKEN` 填入随机强值）→ 构建单二进制 → 启动。

### 2.2 手动构建与运行

```bash
cp .env.example .env            # 按需编辑，至少设置 SAL_MCP_TOKEN
go build -o server-agent-link ./cmd/server-agent-link
./server-agent-link             # 自动读取 .env；真实环境变量优先
```

### 2.3 交叉编译部署到无 Go 机器

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o server-agent-link ./cmd/server-agent-link
# 拷贝二进制到目标机，配好 .env 直接运行
```

### 2.4 systemd 生产部署

单元模板在 [deploy/server-agent-link.service](../deploy/server-agent-link.service)：

```bash
cp server-agent-link /usr/local/bin/
useradd -r -s /usr/sbin/nologin sal
mkdir -p /var/lib/server-agent-link && chown sal:sal /var/lib/server-agent-link
cp deploy/server-agent-link.service /etc/systemd/system/
# 敏感值（SAL_MCP_TOKEN 等）写入 /etc/server-agent-link.env（chmod 600）
systemctl daemon-reload && systemctl enable --now server-agent-link
```

单元已配置：自动重启、`ProtectSystem=strict` 最小权限、journald 日志。审计行检索：

```bash
journalctl -t server-agent-link -g 'audit'
```

### 2.5 目标服务器前置条件

权限落地使用 POSIX ACL，目标服务器需满足：

1. 安装 `acl` 包：Debian/Ubuntu `apt-get install acl`，RHEL/CentOS `yum install acl`，Alpine `apk add acl`。
2. 被授权目录所在文件系统以 `acl` 选项挂载（`mount -o remount,acl /`，或 `/etc/fstab` 加 `acl`）。

否则 `setfacl` 失败，对应账户状态标记为 `error`（错误原因内联显示在详情页）。

### 2.6 端口注意

部分企业主机防火墙会 DROP 8080/8081 等常见 Web 端口（本机回环也拦）。如果服务已监听但浏览器打不开，先换高位端口（如 `SAL_LISTEN_ADDR=:18080`）再排查防火墙。

## 3. 命令行管理（CLI）

同一个二进制内置 `ctl` 子命令——不改配置文件、不动本地数据目录，直接管理**运行中**的服务（走 REST API）：

```bash
# 凭据通过环境变量提供（密码建议放 shell 私有 env，勿写进脚本）
export SAL_SERVER_URL=http://127.0.0.1:18080   # 缺省从 SAL_LISTEN_ADDR 推导
export SAL_ADMIN_PASSWORD=...                   # 管理员密码（必填）
export SAL_MCP_TOKEN=...                        # 仅 exposed 子命令需要

server-agent-link ctl servers                          # 列出服务器
server-agent-link ctl server-add dev1 10.0.0.5 22 root prod
server-agent-link ctl server-test <server-id>          # 连通测试 + root/sudo/plain 探测
server-agent-link ctl server-enable <server-id> off    # 一键从 MCP 撤下整台服务器
server-agent-link ctl accounts <server-id>
server-agent-link ctl account-add <server-id> coder1 '密码' '/data/repo=rw,/logs=ro' '2026-12-31T23:59:59+08:00'
server-agent-link ctl account-expose <account-id> on   # 暴露开关
server-agent-link ctl account-expiry <account-id> never
server-agent-link ctl account-perms <account-id> '/data/repo=rw'
server-agent-link ctl account-passwd <account-id> '新密码'
server-agent-link ctl account-provision <account-id>   # 重新建户/解锁
server-agent-link ctl account-del <account-id>
server-agent-link ctl exposed                          # agent 视角的当前暴露面（密码打码）
```

`server-agent-link ctl`（无参数）打印全部命令。所有写操作与 Web UI 走同一套 API 与审计。

## 4. 环境变量

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `SAL_LISTEN_ADDR` | 否 | `:8080` | 监听地址 |
| `SAL_DATA_DIR` | 否 | `./data` | 数据目录（SQLite + `master.key` + `admin-password.txt`） |
| `SAL_MASTER_KEY` | 否 | 自动生成 | 32 字节 hex 主密钥，加密库内全部凭据。**一旦写入数据必须保持不变**（见 §10.1） |
| `SAL_MCP_TOKEN` | **是** | — | MCP 端点静态 Bearer token，agent 接入用 |
| `SAL_ADMIN_USER` | 否 | `admin` | 管理员用户名 |
| `SAL_ADMIN_PASSWORD` | 否 | 自动生成 | 首次运行的管理员密码；缺省时写入 `$SAL_DATA_DIR/admin-password.txt`（0600） |
| `SAL_TLS_CERT` | 否 | — | TLS 证书路径（与 `SAL_TLS_KEY` 成对） |
| `SAL_TLS_KEY` | 否 | — | TLS 私钥路径（与 `SAL_TLS_CERT` 成对） |
| `SAL_ENV_FILE` | 否 | `.env` | 覆盖 `.env` 路径 |

> 真实环境变量优先于 `.env`。设置了 TLS 则监听 HTTPS 且会话 cookie 带 `Secure`；未设置则明文 HTTP（生产建议 TLS 或反向代理，管理员登录与凭据都走此通道）。

## 5. 首次运行

1. 若未设 `SAL_ADMIN_PASSWORD`，启动后随机管理员密码写入 `$SAL_DATA_DIR/admin-password.txt`（0600），**不打印到日志/stdout**。
2. 若未设 `SAL_MASTER_KEY`，启动时在 `$SAL_DATA_DIR/master.key` 生成 32 字节随机主密钥。
3. 浏览器打开 `http://<host>:<port>/login`，用管理员用户名/密码登录。
4. 右上角 **EN/中文** 按钮切换界面语言（偏好存浏览器 localStorage）。

主密钥保护：程序拒绝一切可能导致密文不可解的操作——`SAL_MASTER_KEY` 格式非法即启动报错；`master.key` 长度异常拒绝覆盖；「keyfile 缺失但数据库存在」直接报错要求提供原密钥。

## 6. Web UI 使用流程

1. **登录**：`/login` 输入管理员用户名与密码。
2. **添加服务器**：首页「添加服务器」填名称、主机、SSH 端口（默认 22）、管理账户用户名（默认 root）、密码。
3. **测试连通**：服务器列表或详情页「测试连通」做真实 SSH 拨号，验证可达性、凭据正确性、主机指纹，成功后**固定指纹并探测管理能力级别**（`root`/`sudo`/`plain`，显示在状态旁）。主机迁移/重装导致指纹变化时会报 `host key mismatch`，用「重置指纹」或改 `host` 复位。
4. **新建账户**：进入服务器详情页，「新建账户」填用户名、密码、目录权限（`路径=模式` 逗号分隔，如 `/data/a=rw,/data/b=ro`）、到期时间（可空）。提交后平台 SSH 到服务器真实执行 `useradd` + `chpasswd` + `setfacl`。若用户名已存在则重置密码并应用权限（幂等，等价「接管已有账户」）。plain 模式下只能 attach 管理账户本人（见 §6）。
5. **查看账户**：详情页表格列出全部账户，含状态（正常/异常/待建户/已锁定）、目录权限清单、到期时间。异常时内联显示失败原因。
6. **切换「暴露」**：账户行开关，点击即切换并保存。
7. **首页暴露概览**：「已暴露给 agent 的账户」跨服务器汇总 agent 实际能拿到的账户（**不含密码**）。到期账户自动从此处与 MCP 消失。
8. **改权限**：账户行「改权限」编辑 `路径=模式` 列表保存，真实推送 ACL（含撤销被移除目录）。
9. **改密码**：账户行「改密码」重置该 OS 用户密码并同步加密库。plain 模式不支持（返回提示，先在服务器 `passwd` 再同步）。
10. **到期时间**：账户行「到期」设置 RFC3339 时刻（留空=永不到期）。到期后 MCP 立即排除，回收器随后锁定远端。
11. **重新建户**：对已存在 OS 用户重跑密码设置与 ACL（幂等），修复 `error` 状态；对 `locked`（到期锁定）账户执行会解锁并恢复。
12. **删除账户**：先逐目录撤销 ACL，再 `userdel -r`；远端失败保留记录供重试。plain 模式只撤 ACL + 删平台记录，不删 OS 用户。
13. **删除服务器**：先逐个远程删除其全部账户（全部成功才删库），失败保留供重试。

## 7. 管理能力分级（root / sudo / plain）

「测试连通」会自动探测登记账户的真实能力，探测结果（`access_mode`）决定供给路径：

| 模式 | 判定 | 建新用户 | 目录授权 | 到期回收 | 删账户 | 改密码 |
|---|---|---|---|---|---|---|
| `root` | uid 0 | ✅ useradd | ✅ 任意目录 | ✅ usermod -L + nologin | ✅ userdel -r（先撤 ACL） | ✅ |
| `sudo` | 免密 sudo（NOPASSWD） | ✅ sudo 提权 | ✅ 任意目录 | ✅ 同上 | ✅ 同上 | ✅ |
| `plain` | 普通账户，无特权 | ❌ 只能 attach 管理账户本人 | ✅ 仅自己拥有的目录 | ✅ 撤全部授权 ACL | ✅ 撤 ACL + 删平台记录（**不删 OS 用户**） | ❌ 提示在服务器 passwd |

**plain 模式的意义**：共享服务器上你往往只有一个普通 dev 账号，无法 root。此时依然可以用 ServerAgentLink 管理权限——把自己账户 attach 进平台、对自己拥有的目录做 ACL 隔离、把凭据经 MCP 交给 agent。越界访问由内核拒绝（`setfacl` 对非自有目录直接失败），天然兜底。

注意事项：
- plain 模式建账户时用户名必须是管理账户本人，否则 API 返回 400。
- plain 模式改密码：先在服务器上 `passwd` 改真实密码，再在平台上删除该账户记录并重新 attach（用新密码），保持两端一致。
- root/sudo 模式下「重新建户」会同时逆转到期锁定（usermod -U + 恢复 bash）。

## 8. 账户到期与回收

### 7.1 工作机制

1. 账户设置 `expires_at`（RFC3339，如 `2026-12-31T23:59:59+08:00`）。
2. **立即生效**：到期账户从 MCP `list_exposed_accounts` 与首页暴露概览中消失（每次调用实时过滤）。
3. **后台回收**：回收器每 10 分钟扫描一次到期未锁定账户：
   - root/sudo 服务器：`usermod -L` 封密码 + `/sbin/nologin` 封 shell（**不删数据**）；
   - plain 服务器：`setfacl -b` 撤销全部授权目录 ACL（含默认 ACL，隔离等效）。
4. **锁定后**：详情页显示「已锁定」徽标。管理员可选择删除，或改大 `expires_at` 后点「重新建户」恢复（解锁 + 恢复 bash + 重推 ACL）。
5. 锁定失败（如服务器不可达）标记 `error` 记录原因，下轮自动重试。

### 7.2 典型用法

- **临时授权**：给外包/临时任务建账户，设 7 天后到期——到期自动断，无需人工清理。
- **审批即过期**：每次人工审批暴露时顺手设一个到期时间，形成「默认回收」的安全习惯。

## 9. REST API 参考

所有 `/api/*`（除 `/api/login`、`/api/logout`）需登录（`sal_session` cookie）。状态变更方法（POST/PUT/DELETE）额外要求 CSRF：请求带 `sal_csrf` cookie 并以 `X-CSRF-Token` 头回传相同值（浏览器内前端自动处理；脚本调用需自行维护）。

### 鉴权

| 方法/路径 | 说明 |
|---|---|
| `POST /api/login` | `{"username","password"}` → 设置 session + csrf cookie |
| `POST /api/logout` | 清除 session + csrf cookie |

### 服务器

| 方法/路径 | 请求体 | 说明 |
|---|---|---|
| `GET /api/servers` | — | 列表（不含凭据；含 `access_mode`） |
| `POST /api/servers` | `{"name","host","ssh_port","root_user","root_password"}` | 添加 |
| `GET /api/servers/{id}` | — | 详情 |
| `POST /api/servers/{id}/test` | — | 连通性测试 + 能力探测，返回 `{"connected":bool,"host_key","access_mode"}`；成功即固定指纹并记录验证时间 |
| `PUT /api/servers/{id}` | 任意子集；含 `reset_host_key:true` 或更换 `host` 会清空已固定指纹 | 更新 |
| `DELETE /api/servers/{id}` | — | 删除（先逐个远程删账户，全部成功才删库） |

### 账户

| 方法/路径 | 请求体 | 说明 |
|---|---|---|
| `GET /api/servers/{id}/accounts` | — | 列出账户（含逐目录权限、`expires_at`） |
| `POST /api/servers/{id}/accounts` | `{"username","password","exposed_to_agent","expires_at"?,"permissions":[{"path","mode"}]}` | 建户并真实 provision |
| `POST /api/accounts/{id}/provision` | — | 重新建户（幂等；可解锁 locked 账户） |
| `PUT /api/accounts/{id}` | `{"exposed_to_agent"?, "expires_at"?}` | 翻转标志 / 设到期 |
| `PUT /api/accounts/{id}/password` | `{"password"}` | 重置 OS 用户密码并同步加密库（plain 模式 400） |
| `DELETE /api/accounts/{id}` | — | 删户（先逐目录撤 ACL，再删 OS 用户；plain 只撤 ACL 删记录） |
| `GET /api/accounts/{id}/permissions` | — | 列出权限 |
| `PUT /api/accounts/{id}/permissions` | `[{"path","mode"}]` | 覆盖权限（含撤销被移除目录的 ACL） |

字段取值：
- `mode`：`rw`（读写）| `ro`（只读）。
- 账户 `status`：`pending` | `active` | `error` | `locked`（到期回收锁定）。
- `expires_at`：RFC3339 时刻或空串（永不到期）。允许过去时刻（视同立即到期）。

## 10. MCP 接入（agent 侧）

MCP 服务是 **streamable HTTP**，地址 `/mcp`，静态 Bearer 鉴权，只读工具一个。

### 10.1 直接挂载到 MCP 客户端配置

把下面这段加进你的 MCP 客户端配置文件（Claude Code 的 `.mcp.json` / Claude Desktop 的 `claude_desktop_config.json` / 其它客户端同格式，键名以各客户端为准）：

```json
{
  "mcpServers": {
    "server-agent-link": {
      "url": "http://127.0.0.1:18080/mcp",
      "headers": {
        "Authorization": "Bearer <你的 SAL_MCP_TOKEN>"
      }
    }
  }
}
```

> `<SAL_MCP_TOKEN>` 的值在服务端 `.env` 里；`url` 用运行 ServerAgentLink 的主机地址。若你的客户端只支持 stdio 传输，可用社区 `mcp-remote` 之类的桥接器：`npx mcp-remote http://sal-host:18080/mcp --header "Authorization: Bearer <token>"`。

### 10.2 curl 冒烟

```bash
curl -H "Authorization: Bearer <SAL_MCP_TOKEN>" \
     -H "Content-Type: application/json" \
     -H "Accept: application/json, text/event-stream" \
     -X POST \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"list_exposed_accounts","arguments":{}}}' \
     http://sal-host:18080/mcp
```

返回（只含 `exposed_to_agent=1`、服务器 `enabled=1` 且未到期的账户）：

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [{
      "type": "text",
      "text": "{\"revision\":\"2026-11-15T04:00:00Z\",\"accounts\":[{\"server_id\":\"...\",\"server_name\":\"dev1\",\"host\":\"10.0.0.5\",\"ssh_port\":22,\"username\":\"coder1\",\"password\":\"...\",\"tag\":\"prod\",\"expires_at\":\"\",\"directories\":[{\"path\":\"/data/repo\",\"mode\":\"rw\"}]}]}"
    }]
  }
}
```

### 10.3 agent 使用约定

- agent 拿到 `directories` 后，**只在列出的目录内工作**。注意授权粒度是**整棵目录子树**：`ro`（ACL `rx`）允许读取与遍历（含执行目录内已有文件），`rw` 允许读写——授权前请确认子树内没有超出预期的内容，且无法排除个别子路径。
- 多服务器场景按 `tag`（prod/test/项目名）或 `server_name + host` 路由；各账户密码独立。
- **凭据缓存与 revision**：每次调用返回 `revision`（凭据目录全局版本号）。agent 缓存凭据时保存它；下次调用先比对——变化即说明有改密/到期/开关变更，必须刷新本地缓存后再 SSH。
- **自我感知到期**：`expires_at` 随账户透传（空串=永不到期）。agent 可据此判断凭据可用窗口，避免用过期凭据反复重试。
- **OS 层生效滞后**：到期后 MCP 目录立即消失，但远端 OS 锁定由后台回收器执行（10 分钟扫描），最长 10 分钟内旧凭据仍可能登录成功——这是设计内窗口。

### 10.4 访问审计

agent 每次经 MCP 拉取凭据目录都会记录审计行（`audit user=agent ip=<源IP> action=mcp.POST`）。注意平台能审计的是「谁拉取了凭据」；agent 在服务器上的具体行为（执行了什么命令、读了哪些文件）依赖目标机自身的 sshd 日志——建议目标机开启 `sshd LogLevel VERBOSE` 并由 syslog 采集。

> MCP 端点返回**明文凭据**，务必用强 `SAL_MCP_TOKEN` 保护并仅在内网/受信环境暴露。客户端环境记得把服务地址加入 `no_proxy`（企业代理会劫持 127.0.0.1/内网地址的请求）。

## 11. 安全模型与运维

### 11.1 主密钥（务必谨慎）

- 库内全部 root/账户密码用 **AES-256-GCM** 加密，密钥来自 `SAL_MASTER_KEY` 或 `$SAL_DATA_DIR/master.key`。
- **切换密钥来源 / 丢失密钥 = 永久失去所有已存密码。** 程序防误操作：非法格式启动报错；keyfile 长度异常拒绝覆盖；「keyfile 缺失但库存在」报错要求原密钥。
- 生产建议用密钥管理工具保存主密钥并显式注入。

### 11.2 SSH 主机指纹（TOFU）

- 首次成功连接记录目标主机 SHA256 指纹，之后每次校验，不符即拒绝（防中间人）。
- 主机迁移/重装导致指纹变化时复位：`PUT /api/servers/{id}` 带 `"reset_host_key": true`，或直接更改 `host` 字段（自动清空指纹）。

### 11.3 SSH 提权（sudo）

- 平台以登记的管理账户 SSH 登录后执行 `useradd`/`chpasswd`/`setfacl`/`userdel`。
- 非 root（uid≠0）自动改用 `sudo -n` 提权，要求 sudoers 配置 `NOPASSWD: ALL`，否则立即报错（账户标 `error`）。
- 真 root（uid 0）不调 sudo；plain 模式完全不使用特权操作。

### 11.4 登录与 CSRF

- 管理员密码 argon2id 哈希，绝不落明文。
- 会话 HMAC-SHA256 签名 cookie（`HttpOnly`、`SameSite=Strict`、TLS 下加 `Secure`）。
- 登录限流 5 次/分钟/IP（原子计数，不信任 `X-Forwarded-For`）。
- 状态变更接口 double-submit CSRF。

### 11.5 审计

状态变更操作写一行结构化审计到 stdout（systemd 下进 journald）：

```
audit user=admin ip=10.0.0.2 action=account.create object=<id> <username>
```

动作覆盖：`server.create/update/delete`、`account.create/update/delete/permissions/password/provision`、系统回收 `account.lock`。检索：

```bash
journalctl -t server-agent-link -g 'audit'
```

## 12. 备份与恢复

```bash
./deploy/backup.sh [数据目录] [输出目录]     # 默认 ./data ./backups
```

备份包含 SQLite 库 + `master.key`（+ `admin-password.txt`）。**二者必须成对保留**：丢失 `master.key` 即库内全部密文永久不可解。有 `sqlite3` 时走在线快照（一致性保证），无则直接拷贝（建议停服窗口执行）。恢复：解包到数据目录后重启（schema 迁移自动执行）。建议 crontab 定期执行并异地保存。

## 13. 常见故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 服务已监听但浏览器打不开 | 主机防火墙 DROP 该端口（8080 常被企业策略封） | 换高位端口 `SAL_LISTEN_ADDR=:18080` |
| 账户状态 `error` | 目标不可达 / 密码错 / 目录不存在 / 无 ACL 包 | 修正后点「重新建户」或调 provision |
| `error`（权限不足） | 管理账户非 root 且无免密 sudo | 配 `NOPASSWD: ALL`，或改用真 root；无特权场景用 plain 模式 |
| `host key mismatch` | 目标指纹已变化 | `reset_host_key` 或改 `host` 复位 |
| plain 模式建「其他用户名」返回 400 | attach-only 只能 attach 管理账户本人 | 只 attach 管理账户；需要多账户请用 root/sudo 模式 |
| plain 模式改密码返回 400 | 无特权无法 chpasswd | 服务器上 `passwd` 后删除重建账户记录 |
| MCP 调用 000/超时 | 客户端走了代理 | 把服务地址加进 `no_proxy` |
| `SAL_MCP_TOKEN must be set` | 未设 token | 设置后重启 |
| 解密失败（`message authentication failed`） | 主密钥变了 | 恢复原 `SAL_MASTER_KEY` / `master.key` |
| 到期账户仍出现在 MCP | 缓存 | MCP 每次调用实时过滤，重新调用即可 |
